# 以逐步選擇建立原子玩家行動

CLI 與 bot 不需從所有參數組合中選擇一個完全展開的玩家行動；它們先選擇行動類型，再依規則引擎回傳的選擇要求逐步提供目標、模式、費用與順序等資料。若規則只允許在效果結算期間作出選擇，引擎會建立待決選擇並暫停推進，直到指定玩家回答。CLI 與 bot 共用完全相同的協定。

打牌或啟動能力的宣告由 `DeclarationTransaction` 在隔離候選狀態中執行。交易保存起始 revision、候選區域移動、參數／模式／目標、費用快照、候選事件、trigger buffer 與隔離的 PRNG cursor。費用支付若依法新增模式或目標，只重走規定步驟，不重算已固定 cost。正式 GameState 在交易完成前不變。

只有完整合法的 activation 才將候選狀態、PRNG cursor 與事件原子提交。取消、過期、無法支付或最終非法時整筆丟棄，視為未採取行動：不留下區域移動、費用、事件、trigger 或亂數消耗。Activation 一旦成立，費用便正式支付；日後 fizzle 或 negate 不回滾費用。

交易中的暫定 chance outcome 不能在 commit 前洩漏給操控端。玩家只能在規則仍允許撤回宣告的階段主動取消；進入需要取樣亂數的費用支付階段後，只能完成規則要求的後續選擇或讓交易依法失敗。Rollback 的暫定結果不進入 PlayerView 或事件歷史，避免玩家先窺視亂數再改選其他行動。

## 曾考慮的方案

預先列舉每個完整玩家行動能讓提交介面保持單步，但目標、模式、費用與順序的笛卡兒組合會快速膨脹，也不適合只能在結算時決定的選擇。直接在正式 GameState 上逐步修改再嘗試 undo，則很容易遺漏 PRNG cursor、trigger、knowledge 或 derived state，無法證明非法宣告完全無副作用，因此不採用。
