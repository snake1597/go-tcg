# 操控端只能取得玩家視角

CLI 與 bot 等操控端不得直接讀取規則引擎的完整單局狀態，而只能取得指定玩家依規則可見的 `PlayerView`。Game Module 為每位玩家維護 `KnowledgeState`，表示該玩家在目前時間點對各實體具有的查看與追蹤權；不能只用「公開區域／自己的私有區域」判定資訊權限。

`CardInstanceID`、`ObjectID` 等穩定內部身分永不提供給操控端。PlayerView 改用限定於玩家、追蹤期間及 state revision 的不透明 `ViewHandle`：規則仍允許追蹤同一實體時可保持穩定；洗牌、隨機放回牌庫或其他會使追蹤權消失的操作必須撤銷舊 handle。卡牌日後重新可見時會取得新 handle，不能藉穩定 ID 推斷其隱藏位置。

Reveal 等曾公開內容保留在玩家可見的事件歷史中，使玩家可以回顧依法能記錄的資訊；該歷史不會重新關聯已因隨機化而失去追蹤的卡牌。所有操控端仍透過相同的合法玩家行動與逐步選擇協定操作，且只能以當前 revision 的 ViewHandle 提交；過期、跨玩家或已撤銷的 handle 必須拒絕而不改變狀態。CLI 與 bot 採用完全相同的投影規則，不給 bot 額外資訊。

## 曾考慮的方案

把完整狀態直接交給 bot 能簡化首版串接，但策略程式很容易無意間使用隱藏資訊，而且日後很難證明公平性或改接只能取得有限資訊的遠端玩家。另一方案是直接將內部 ID 放入 redacted view；雖然省去 handle 對映，卻會形成跨洗牌的追蹤旁路，因此不採用。
