# 首版以 Go 實作卡牌行為

首版以型別安全的 Go 註冊每張卡牌，並用抽牌、傷害、目標選擇與觸發能力等可重用效果元件組合常見行為；特殊卡牌可使用專屬 Go handler，但仍只能透過規則引擎提供的操作改變單局狀態。靜態卡牌資料可存放於資料檔，但首版不解析自然語言卡面、不建立卡牌 DSL，也不嵌入 Lua、JavaScript 或 Starlark 等腳本語言；每張支援卡牌都必須具備獨立規則測試。

## 曾考慮的方案

DSL 或腳本能在不重新編譯 Go 程式的情況下新增卡牌，但目前只有一副固定牌組，尚不足以抵銷語言解析、驗證、除錯、版本管理、安全隔離與確定性控制的成本。未來若卡池規模證明 Go 實作成為瓶頸，可讓新表示法建立在既有的效果元件之上。
